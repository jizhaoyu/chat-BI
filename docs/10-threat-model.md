# 威胁模型

本项目的核心威胁来自不可信自然语言、不可信模型输出、不可信外部数据源和潜在越权用户。安全目标是让任何不确定内容都无法绕过确定性审批和只读执行边界。

## 1. 资产

- 平台数据库中的用户、权限、数据源配置、元数据和审计记录。
- 外部分析数据源中的业务数据。
- 数据源凭据、平台主密钥和模型 API 密钥。
- SQL 候选、审批记录、执行结果摘要和用户反馈。

## 2. 主要攻击面

| 攻击面 | 风险 | 防护 |
|---|---|---|
| 自然语言问题 | 提示注入、诱导越权 | 模型只生成候选，候选必须经过网关 |
| 模型输出 | DDL/DML、多语句、幻觉对象 | AST 白名单、对象权限、默认拒绝 |
| JDBC 配置 | 任意连接参数、凭据泄露 | 结构化配置、加密存储、响应脱敏 |
| 元数据暴露 | 用户推断未授权表列 | 检索阶段按权限裁剪元数据 |
| approvalId | 重放、替换 SQL 或用户上下文 | 绑定哈希、用户、租户、版本和过期时间 |
| 查询执行 | 慢查询、超大结果、连接池耗尽、进程中断遗留运行态 | 超时、并发、行数、大小限制、陈旧运行恢复 |
| 日志和错误 | 泄露密码、SQL 栈、大批业务数据 | 错误分类、字段脱敏、摘要化审计 |
| 图表规格 | 脚本执行、外部资源加载 | JSON Schema 白名单、禁止脚本和 URL |

## 3. 关键安全不变量

- 没有有效 `ApprovedQuery`，任何 SQL 都不能进入执行器。
- 模型永远不能接触数据库凭据。
- 外部数据源连接池永远不能复用平台库事务或凭据。
- 权限校验必须覆盖投影、过滤、连接、分组、排序和子查询中的对象。
- 解析器无法完整理解的 SQL 必须拒绝。
- 日志中不得出现密码、完整 JDBC URL、模型密钥或完整敏感结果集。
- 审批消费与执行记录创建必须先在平台短事务提交，外部查询阶段不得存在平台事务。
- 执行接口不得接受调用方 SQL、数据源或资源限制覆盖值，执行端口只接受 `ApprovedQuery`。

## 4. MVP 暂不覆盖

- 多租户商业化隔离审计。
- 行级权限表达式和动态数据权限。
- PostgreSQL 方言完整支持。
- 生产级密钥管理系统集成。
- 大规模并行查询和 OLAP 加速。

这些能力进入范围前必须更新本文档、测试计划和开发路线。
