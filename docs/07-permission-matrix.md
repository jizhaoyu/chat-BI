# 权限矩阵

MVP 为单租户交付，但所有鉴权、查询和审计逻辑必须携带 `tenant_id`。以下矩阵用于指导 Spring Security、服务层校验和接口测试。

## 1. 角色能力

| 能力 | SYSTEM_ADMIN | DATA_ADMIN | ANALYST | VIEWER |
|---|---:|---:|---:|---:|
| 管理用户与角色 | 是 | 否 | 否 | 否 |
| 查看数据源列表 | 是 | 是 | 仅授权 | 仅授权 |
| 创建/修改数据源 | 否 | 是 | 否 | 否 |
| 测试数据源连接 | 否 | 是 | 否 | 否 |
| 启用/禁用数据源 | 否 | 是 | 否 | 否 |
| 同步元数据 | 否 | 是 | 否 | 否 |
| 配置表列权限 | 否 | 是 | 否 | 否 |
| 配置业务术语和敏感等级 | 否 | 是 | 否 | 否 |
| 创建分析会话 | 否 | 是 | 是 | 否 |
| 生成 SQL 候选 | 否 | 是 | 是 | 否 |
| 校验 SQL 候选 | 否 | 是 | 是 | 否 |
| 执行已批准查询 | 否 | 是 | 是 | 否 |
| 查看自己会话结果 | 否 | 是 | 是 | 是，限分享结果 |
| 提交反馈 | 否 | 是 | 是 | 是，限分享结果 |
| 查看审计日志 | 是 | 是，限数据源范围 | 否 | 否 |
| 运行评测集 | 是 | 是 | 否 | 否 |

## 2. 资源访问规则

- 所有接口先校验登录身份，再校验角色，再校验租户和资源归属。
- `DATA_ADMIN` 只能管理当前租户内数据源和元数据。
- `ANALYST` 只能选择被授权的数据源、表和列。
- `VIEWER` 不允许触发 SQL 生成、校验或执行，只能查看已分享且已脱敏的结果。
- 审计日志不能向普通分析用户开放，避免泄露越权对象名称和安全策略细节。

## 3. 数据权限粒度

对象权限以 `data_permission` 为准：

- `DATA_SOURCE`：是否可见和可选择数据源。
- `SCHEMA`：是否可见 Schema 下对象。
- `TABLE`：是否可用于候选生成和执行。
- `COLUMN`：是否可投影、过滤、分组、排序和连接。

列权限可以比表权限更严格。表授权不自动意味着所有列可返回。

## 4. 敏感等级

| 等级 | 含义 | 默认行为 |
|---|---|---|
| `PUBLIC` | 普通分析字段 | 可返回 |
| `INTERNAL` | 内部业务字段 | 仅授权用户可返回 |
| `SENSITIVE` | 手机号、邮箱、地址等 | 默认脱敏 |
| `SECRET` | 身份证、密钥、账户余额等高敏字段 | 默认禁止原样返回 |

敏感列即使允许参与过滤或聚合，也不得在日志、图表、导出和解释中泄露原始值。

## 5. 接口测试要求

- 每个主要接口至少覆盖未登录、角色不足、租户不匹配、资源不存在和资源越权。
- SQL 执行链路必须覆盖“候选可见但列不可执行”的场景。
- 审计查询必须验证普通用户无法通过错误响应推断越权对象详情。
