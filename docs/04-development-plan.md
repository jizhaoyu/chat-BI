先实现不依赖大模型的安全查询内核，再接入自然语言生成。这样可以用确定性测试锁住信任边界，避免“先有演示、后补安全”。

## CBI-P1 工程骨架与样例数据源

状态：`completed`

验收证据：Java 21 快速测试与 GitHub Actions 双库 Compose、只读授权、Testcontainers 集成测试均通过。

- 创建 Spring Boot/Maven 工程、模块边界、统一错误响应和认证骨架。
- 配置平台 MySQL、Flyway、Testcontainers 和 CI。
- 准备独立样例销售数据源及严格只读账号。
- 建立平台库/分析库两套连接与事务边界测试。

完成标准：应用可管理数据源配置，样例只读账号无法执行任何写操作。

## CBI-P2 元数据与权限

状态：`in_progress`

- 实现数据源连接测试、加密存储和受限连接池。
- 实现 MySQL 元数据同步、活动快照和差异展示。
- 实现表列授权、业务名称、同义词和敏感等级。
- 增加元数据同步失败恢复及越权测试。

完成标准：用户只能查看和选择被授权的元数据，快照切换不暴露半成品。

## CBI-P3 SQL 安全网关

状态：`pending`

- 验证并选定 AST 解析器和支持的 MySQL 语法子集。
- 实现语句类型、表列、函数、通配符、LIMIT 和多语句规则。
- 建立 `ApprovedQuery` 与短时批准标识。
- 建立恶意 SQL 与方言绕过回归集。

完成标准：安全用例通过；未持有有效批准对象的裸 SQL 无法进入执行器。

## CBI-P4 受控执行

状态：`pending`

- 实现只读执行、超时取消、并发配额、最大行数和响应大小限制。
- 实现结果 Schema、脱敏、截断标记、摘要和审计。
- 接入可选 EXPLAIN 预算策略。

完成标准：慢查询、超大结果、连接池耗尽和取消场景均有自动化测试。

## CBI-P5 AI 生成与图表

状态：`pending`

- 接入模型适配器和结构化候选输出。
- 实现相关元数据筛选、候选解释和生成/执行分离流程。
- 实现受限图表 JSON Schema、后端校验和结果解释。
- 模型不可用时保留手工 SQL 安全验证演示能力。

完成标准：固定问题可生成并执行正确 SQL；幻觉对象和不安全候选被确定性拒绝。

## CBI-P6 评测与作品集交付

状态：`pending`

- 建立正常题、歧义题、越权题、注入题和高成本题评测集。
- 输出执行正确率、安全拒绝率、误拒率和分段耗时。
- 完善日志、指标、演示脚本、架构图与面试材料。

完成标准：全套测试通过，评测结果可复现，并诚实记录支持语法与限制。

## 风险与决策点

- AST 解析器对 MySQL/PostgreSQL 方言覆盖不同：MVP 先锁 MySQL 子集。
- 判断账号绝对只读并不总能仅靠 JDBC 完成：部署说明必须要求 DBA 侧最小授权，并用负向写入测试验证样例环境。
- `EXPLAIN` 本身也可能有代价：设置独立超时，不能当作万能安全机制。
- 语义层过大容易失控：MVP 只做业务名称、同义词、指标和敏感等级。
